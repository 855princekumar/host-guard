# Security audit: host-guard 0.3.0

Open confirmed findings: 0

| | |
|---|---|
| Tool | [security-audit skill](https://github.com/cloudflare/security-audit-skill) by Cloudflare, commit `c1c8a8c` |
| Runs | run 1: `standard` profile on `e2b6bbe` (29 units, 4 hunter waves); run 2: `quick` profile on `ffdce33` (every run-1 record re-verified, new code hunted) |
| Method | every candidate reproduced in a sandbox (Docker, `--network none`, read-only source), then checked by a fresh verifier |
| Fixes | on the branch `audit-fixes`, each with a test that fails without it |
| Result | 9 confirmed (1 medium, 8 low), 6 needing validation, 2 rejected; no critical or high |

Nothing found gives code execution, credential theft or a way past authentication. The
confirmed findings are ways for someone with less access (a local user, an app container,
a feed) to blind host-guard's alerting or annoy the panel's admin. All are fixed.

## Confirmed, fixed

| # | Severity | Finding | Fix | Test |
|---|---|---|---|---|
| 1 | medium | The miner quarantine copied the program as root without a size limit: a sparse 60 MiB file filled the state disk and every later watch run failed before its mail | copy at most 64 MiB, never through a link, partial copies removed; a failed state write no longer stops the lockdown or the mail | `test_a_quarantine_copy_is_capped_and_never_follows_a_link` |
| 2 | low | Panel: `Content-Length: -1` passed the size check, so the whole stream was read before any check | only a plain number up to 8192; 20 s socket timeout; `MemoryMax=256M`, `TasksMax=64` | `test_a_negative_or_signed_length_is_refused_before_any_body_is_read` |
| 3 | low | Panel: every visitor arrives as 127.0.0.1 through the tunnel, so 10 bad sign-ins blocked the real admin too | the address block refuses guesses but never the right name, password and code | `test_after_ten_failures_an_address_gets_no_more_guesses_but_the_admin_still_gets_in` |
| 4 | low | The installer ran `touch` as root through links planted in the `--web-logs` folder (a compromised web container could create `/etc/nologin`) | refuses a link there; creates missing files without following one | reviewed; covered by the fresh-install and lifecycle jobs |
| 5 | low | A mail held by flood protection started its problem's 6 h cooldown, so the real alert waited 6 hours | the cooldown starts only with a mail that went out | `test_a_held_mail_does_not_start_the_cooldown` |
| 6 | low | A certificate date that did not parse crashed every health and boot run | the date is read safely; a crashing check is reported as its own problem and the others still run | `test_a_broken_certificate_date_or_lag_never_stops_the_health_run` |
| 7 | low | A lone surrogate in a feed dropped an urgent advisory batch for good (marked seen before the mail failed) | text is cleaned before mailing; seen only after the mail went out | `test_text_that_is_not_valid_unicode_still_mails` |
| 8 | low | Invalid UTF-8 or a non-numeric lag from the replica crashed health, report, boot and patch window | every command's output is decoded with replacement; the lag is read defensively | `test_a_broken_certificate_date_or_lag_never_stops_the_health_run`, `test_text_that_is_not_valid_unicode_still_mails` |
| 9 | low | Invalid UTF-8 in a container's `pip list` stopped the early warning on every run | the same decoding fix; one container's failure is a note, not a crash | `test_text_that_is_not_valid_unicode_still_mails` |

## Needing validation: closed by a fix instead

| Lead | Decision |
|---|---|
| A crafted SSH user name could look like a root login and trigger the lockdown | fixed: only lines that start with sshd's own `Accepted <method> for root from` count (`test_a_user_name_cannot_forge_a_root_login`) |
| A small compressed feed answer could expand to gigabytes | fixed: 200 MiB limit before and after decompression (`test_a_feed_answer_cannot_expand_without_limit`) |
| The restore test's database password was visible in `/proc` and the database sat on the default bridge | fixed: the password comes from a root-only env file and `MYSQL_PWD` inside the container; `--network none` |
| A backup was decrypted before its checksum was compared | fixed: a backup whose checksum differs is never opened |
| Any `v*.*.*` tag on any commit would publish to PyPI | fixed: the release gates require the tag to be on `main` (which only takes pull requests with every check green) |
| Thousands of planted programs could make a critical mail too large to deliver | fixed: mails are cut at 200 KB with a note where the rest is |
