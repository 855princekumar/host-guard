# Security audit: host-guard 0.5.0

Open confirmed findings: 0

| | |
|---|---|
| Reviewer | an independent review pass that did not see the authors' reasoning, given only the code and this threat model |
| Scope | the changes since 0.4.0 (`6916176..` the 0.5.0 branch): the advisories (`guard/shield.py`), approvals by reply, dashboard and console (`guard/approvals.py`), the public-only fetcher and the reader in `hostguard.py`, the root side of the panel's outbox, and the panel's Advisories and Sources pages |
| Threat model | (1) anyone who can mail the server's inbox; (2) a taken-over panel process writing any outbox file; (3) a hostile or compromised feed, web page or reader; (4) a stolen panel session without the mailbox; (5) shell injection through finding, package, container or image values; (6) races between the shield run, the reply reader and the outbox |
| Run | every suspected issue confirmed by a code trace or reproduced with pytest in a `python:3.12-slim` container; the fixes are each covered by a test named after the finding |
| Result | 6 confirmed (1 high, 3 medium, 2 low), all fixed below. The new fuzz tests found a seventh before the review: listed under Hardened |

## Confirmed, fixed

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | high | **A taken-over panel could approve anything as any admin**, including the two-admin reboot and source changes. Root believed the outbox file's `email`, and the confirm code was made by the panel itself, so root had nothing to check. | **Root makes the code.** The panel only asks for it (`change-request` with a random change id). Root mails a 6-digit code derived from its own key and bound to that admin, that change id, a fresh nonce and exactly that change, described in root's own words. Only a `confirm` carrying that code makes the change, at most 5 tries per change. The old `approve`, `source-add` and `source-remove` kinds are refused. Tests: a taken-over panel's direct writes and guessed codes change nothing. |
| 2 | medium | **A cookie thief could swap the change an admin's code confirmed:** a throttled request still replaced the waiting change while the earlier code stayed live. | Fixed by finding 1's binding: a code confirms only the change it was mailed for, whatever waits in the session. The panel also refuses a change outright when throttled (5 change requests per admin in 10 minutes). Test: the code for change A does not confirm change B. |
| 3 | medium | **One hostile feed or page could stop the advisories:** lazy regexes (`<item ... </item>`, `<script ... </script>`) took tens of seconds on 100 KB of unclosed tags, and about 1 MB outlasted the 45-minute run. No findings, mails or fixes until the source changed. | Linear parsing with `str.find` for items, titles, links and script, style and noscript blocks; tag stripping that cannot backtrack (`<[^<>]*>`); context text capped at 1 MB. Tests: 200,000 unclosed tags parse in under 3 seconds. |
| 4 | medium | **A hold approved during a shield run was undone:** the run saved its own older copy of the findings, and the automatic fix still ran. | The run keeps what an admin did meanwhile: status, holder, reason, fixes and due time. The status is re-read just before any fix, and an admin's change wins. Test: a hold made mid-run survives, and the due fix is skipped. |
| 5 | low | **Newer mail could hide a reply:** the reader took the newest 50 unread messages, so 50 later mails (or ordinary traffic) kept an admin's reply unread for two days. | The reader keeps the last UID it read (per UIDVALIDITY) and reads everything after it, oldest first. It moves on only once a mail is read to the end. Test: 60 mails, then a reply, and the reply is acted on. |
| 6 | low | **The DMARC check matched outside the dmarc result:** text the sender controls in another result (a quoted envelope sender, a comment) could look like `dmarc=pass`. Also, an address only inside an encoded word (`=?utf-8?q?sec=40example.com?=`) was taken as the sender. | Quoted strings and comments are removed before the header is split into results; exactly one `dmarc` result must exist, and it must pass for the From domain. A From containing an encoded word is refused. Tests: four crafted headers and the encoded From are refused. |

## Hardened as well

- **Found by the new fuzz tests before the review:** Python's own address parser raises on some malformed headers. One such mail, left unread, would have stopped every reply behind it. Now it is refused and logged, and the rest go on.
- **Found by the red team:** an action line with more after the code (`HOLD hg-...; touch /tmp/x`) was taken as `HOLD hg-...` and the rest ignored. Nothing was ever run, but a line that says more than the action is now refused as not understood: the action and the code alone, a full stop at most.
- **UID order:** UIDs are sorted as numbers, not as bytes, so 10 does not come before 9.
- **Wrong-code mail:** a wrong code mails the admin with the tries left, so a wrong confirm is never silent.

## Checked and holding

- **Shell injection:** every value that reaches a shell in the advisories is quoted (`shlex.quote`): packages, containers, Compose folders, files and services, images, `.deb` files and paths. A `docker tag` id runs only after a `sha256:` prefix check.
- **Approval targets:** action targets are an exact pattern (8 hex characters, or `now` for a reboot).
- **Outbox reads:** the outbox is read through its open folder, without following links, and only small regular files of the panel's user.
- **The fetcher:**
  - The address is checked on the socket actually opened, so DNS rebinding does not help.
  - Redirects are https only and checked again.
  - IPv4-mapped addresses are not taken as public.
  - Gzip output is bounded.
- **Reply codes:**
  - 128-bit HMACs, compared in constant time and used once, then checked again when approving.
  - Message-ID is used only to skip duplicates.
  - Quoted text and HTML blockquotes never count.
  - Exactly one From is required.
  - The same admin cannot approve twice.
- **Keys and pages:** the approvals key is created exclusively, without following a link, with mode 0600. The panel's pages escape every field from the export.

Not covered by this scoped pass: code unchanged since 0.4.0 (see [0.4.0.md](0.4.0.md) and earlier).
