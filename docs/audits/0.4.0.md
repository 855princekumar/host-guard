# Security audit: host-guard 0.4.0

Open confirmed findings: 0

| | |
|---|---|
| Tool | [security-audit skill](https://github.com/cloudflare/security-audit-skill) by Cloudflare, commit `c1c8a8c` |
| Scope | the changes since 0.3.1 (`03889c8..` the 0.4.0 branch): dashboard sign-in by email and a mailed code, the panel's outbox, the root mailer `hostguard panel-outbox` and its systemd units, the install script |
| Run | `quick` profile scoped to the diff: 2 hunters, a coverage critic, a fresh verifier per candidate; every confirmed finding was reproduced in a container with no network, with a dummy user, scratch folders and a local mail catcher |
| Result | 4 confirmed (1 high, 1 medium, 2 low), all fixed below; 2 findings of the 0.3.0 audit re-checked and still fixed |

## Confirmed, fixed

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | high | A taken-over panel could make the root mailer empty any folder: the panel's user owns the outbox's parent, so it could replace the outbox with a link (`ln -s /etc outbox`), and root listed and removed through it | the mailer opens the outbox once without following a link, requires a 0700 folder of the panel's user, and reads and removes every entry through that open folder (`dir_fd`), never by path; a folder inside it is emptied the same way; a hard-linked file is not read; the mail service is sandboxed (`ProtectSystem=full`, `ProtectHome=read-only`, `PrivateTmp`, `NoNewPrivileges` and more). Tests: a swapped link leaves the target untouched; an outbox others can write, or of another user, is not read |
| 2 | medium | Once the shared 127.0.0.1 failure block tripped (10 wrong codes for any addresses), wrong guesses returned early and no longer counted against the code, so a code could be guessed without limit while the right one still signed in | every wrong try counts against the code (5 burn it) before the block answers; test: 5 wrong tries during the block burn the code |
| 3 | low | Any visitor who knew an admin's address could replace that admin's code with a new request, burn it with 5 wrong tries, or use up the address's 3 requests | a code belongs to the browser that asked for it (the hash of an `hg_ask` cookie, HttpOnly, SameSite=Strict, 15 minutes): another browser can neither replace nor burn it, nor use a stolen code; 3 requests per browser and address, 10 per address in all, in 10 minutes |
| 4 | low | Sign-in notices to all admins had no limit (and are never held), so a taken-over panel could flood every admin | at most 5 notices per address and 20 an hour, counted by root in `panel-mail.json`; test with 12 notices |

## Accepted

| Item | Why |
|---|---|
| Someone who can reach the dashboard can still use up an address's 10 requests, or the root mailer's 5 codes per address in 15 minutes, so the admin waits for the next window | reaching the dashboard needs a tunnel to the server (it listens on 127.0.0.1 only); every request is in the audit log with the address; without the limits the same person could flood the admin's mailbox instead |
| Sign-in mails take entries in the shared 200-entry mail log | they are now bounded (at most 50 an hour) and show in Recent mails, which is where an admin should see them |

## Hardened as well

- A code must be 6 ASCII digits (Python's `isdigit` also takes other scripts' digits).
- A `.tmp` file in the outbox with a time in the future is removed instead of kept (it kept the path unit firing).
- The audit table keeps at most 100,000 rows, on top of 180 days.
- Codes and requests of earlier 0.4.0 drafts are dropped on start (they were not bound to a browser).

## Checked and holding

Recipients are an exact lowercase match against the admin addresses (CR/LF, commas, display names and Unicode case variants add nobody); code mails stop at 5 per address in 15 minutes and 30 an hour; codes come from `secrets`, are stored as a salted SHA-256, compared in constant time and used once under a lock; the answer is the same for every address; no session fixation; sessions from the password era stop working; the new forms need their form token, the same origin and the right Host.

Not covered by this scoped pass: code unchanged since 0.3.1 (see [0.3.1.md](0.3.1.md) and [0.3.0.md](0.3.0.md)).
